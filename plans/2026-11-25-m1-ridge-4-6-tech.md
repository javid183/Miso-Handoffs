## Why

## Approach

The player controller already skips units tagged `Status.Inactive` (`skipTurnTagsQuery` on `Content/Controllers/PlayerController.prefab`; `FactionControllerBase.IsSelectableUnitCell` / `IsUnitTurnSkipped`). Precedent: `Lucy_Decoy.prefab` carries the tag statically.

1. New feature component in `Features/Onboarding/` (e.g. `HoldUnitsUntilSignal`): a list of units; at level start (before the first family turn) it gives each unit the `Status.Inactive` tag at runtime; `Release()` removes it. Started/released by the same "Ridge Switches" `SignalAction` / `SignalSequence` pattern `StageDefeatRelax` and `PouchHint` use. Only removes a tag it added (don't strip a tag something else set). Restores on level restart (check `FactionControllerBase` restart path, `RefreshExhaustionAfterRestart`), so a restarted level holds Linda again.
2. Wiring (`MissionWiring.Ridge*.cs`, idempotent): add the component to `GB_m1-ridge` with Linda; add a release `SignalSequence` as the first step of `M1Ridge_Catch_SequentialSequence` (S1's on-complete: it runs both when Mark reaches the ledge and on the turn fallback), so Linda is free before her bar unlocks. Append once (the seed keeps existing lists).
3. Visual: if the skipped unit doesn't look exhausted/greyed, mark it exhausted while held (`GUnit.MarkExhausted` / `MarkEnergetic` on release), so the player sees she can't act. Report what it looks like.
