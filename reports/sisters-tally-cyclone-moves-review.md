# Review: Sisters' tally counts kills a Cyclone makes on its own moves

Reviewer: miso-reviewer    Branch: thj/onboarding    Verdict: **FIX** (two tests would fail; production logic is sound)

Scope read: `SistersTallyListener.cs` diff, `Editor/SistersTallyTests.OutOfAbility.cs` (+ `.meta`), against `GlobalEventBus`, `AEffectCompound`, `RuntimeAbility`, `AbilityOrchestrator`, `CombatLevelRunHandler`, `FactionControllerBase`, `GUnit`, `RuntimeAAttribute`, the sibling tally tests and `.meta` files.

## Must fix

1. `Editor/SistersTallyTests.OutOfAbility.cs:72-77` (`OutOfAbility_AnAbilityWithoutAnOwnerCountsNothing`) fails. `new RuntimeAbility()` has a null `_owner` orchestrator and `RuntimeAbility.Owner` is `_owner.Unit` (`RuntimeAbility.cs:55`), so `RecordEffectOutsideAbility` throws a NullReferenceException at `SistersTallyListener.cs:228`. `Guard` catches it and calls `Debug.LogException`, and the EditMode runner fails the test on the unhandled exception log. Fix, either: make the test an orchestrator with a null unit (`MakeAbilityOwnedBy(null)`), which exercises the real "no owner" case (`!owner`) and does not throw; or guard the production line. Prefer the first; an uninitialized ability never reaches the bus in play.
2. `Editor/SistersTallyTests.OutOfAbility.cs:101` (`OutOfAbility_AnAbilityInProgressCountsOnlyThroughTheDamageEvent`) fails at its last assertion. `RecordDamage` ignores the amount and does not consult `_killedByPlayer` (`SistersTallyListener.cs:205-216`), and `SistersTally.RecordKill` does not dedupe (`SistersTally.cs:140`; the existing tests rely on that). So the second `onUnitDamageDone(ability, _goblin, 0f, true)` counts Linda again (2, not 1). The core run handler never raises a damage event with zero reduction (`CombatLevelRunHandler.cs:830`), so the scenario is unreal: delete line 101 and its comment words "and a stale damage report" (keep the late effect report check).

## Should fix

No action needed if must-fix 1 takes the test route.

## Correctness traces

- **Order for one hit.** `AEffectCompound.Apply` runs `effect.Apply` (health set, which runs `onMinReached` synchronously inside `RuntimeAAttribute.SetValue`, `RuntimeAAttribute.cs:82`) and only then raises `onAbilityEffectPerformedOn` (`AEffectCompound.cs:165-167`). The unit's Die wiring is not in code (prefab-side `onMinReached` event), so I could not prove it, but the attribute raises it synchronously before returning, so `unitDied` almost certainly precedes the report. The new path itself does not depend on it (it uses the at-minimum-health check); only the Bloom conversion does. Play check still wanted (as the implementer said).
- **`activationStarted` precedes effects.** `RuntimeAbility._ActivateAbility` invokes the `onActivation` callback (which raises `abilityActivationStarted`) before `preset.Activate` runs the effects, so an in-progress ability's own effect reports are ignored and its kill reaches the damage event at `abilityPerformed` (via `CombatLevelRunHandler.OnAbilityComplete` -> `onAbilityPerformedOn` -> `onUnitDamageDone`). The completion-time reports (`RuntimeAbility.cs:326`) also come before `abilityPerformed` (it is raised later with a delay, `FactionControllerBase.cs:1014`). No double count from the two paths: a later report on the same corpse is blocked by `_killedByPlayer`, and a corpse cannot reach a later damage event (health snapshot diff would be zero).
- **Who raises started/performed.** Controller abilities, Lucy's and Linda's Family Role abilities and Linda's Watch reaction raise both (`LucyFactionRoleHandler.cs:224-234`, `LindaFactionRoleHandler.cs:80-90`), so Lucy's finisher is "in progress" and counts once through the damage event (D-449 holds). Duo partner abilities, pass-by (`UnitsPassByHandler.cs:142`), Mark/John passives raise neither: for a sister's pass-by or passive kill the new path is the first thing to count it. That is consistent with "a kill counts for who made it", but it is a behavior change beyond Cyclones (see risks).
- **Duo.** `_duo != null` blocks the new path for the whole bracket (the bracket counts via `RecordDeath`, and `CountForBoth` fills `_countedForBoth`, which `RecordDamage` checks); the trigger ability is skipped too. Bracket closes on the trigger's `abilityPerformed` or turn end.
- **Bloom.** Arrow in progress: its reports are ignored, the damage event converts at `abilityPerformed`. Late copy after `abilityPerformed`: report goes to `RecordDamage`, `_diedInBloom.Remove` -> `CountForBoth` -> both sisters once; the repeat is blocked by `_killedByPlayer`. Correct per D-449.
- **Leaks / symmetry.** `RemoveListeners` mirrors every `AddListener` including the new one; `ForgetLevel` (called by `Connect` and `Disconnect`) clears `_killedByPlayer` and `_inProgress`; `_inProgress` also clears on turn end and per ability on `abilityPerformed`; `OnUnitBorn` clears `_killedByPlayer` for revivals. The bus is per level, so references die with it.
- **Core untouched by this change.** The change touches only the three tally files. `git diff` on `Core/` shows two modified AI files (`AISystem/Runtime/AIFactionBrain.cs`, `AIUnitBrain.cs`, last written 2026-10-29), which predate this work and are not in the report; the coordinator should confirm they are someone else's pending work and keep them out of this commit.

## Wrong-source kills

- Burn ticks, hazards, enemy abilities: no ability report, or the owner is not a player sister, so nothing counts. Enemy-owned effects return at the owner check. A non-sister player kill (John, Mark) is not counted (owner check), and a kill that reached the damage event is blocked by `_killedByPlayer`.
- Residual (low): a corpse killed by a non-sister through a path with no damage event (passives, pass-by) and then named again in a sister's out-of-ability report would count for her. Dead units are unplugged from cells, so area/target resolution should not list them; only a target list captured before the death could (`preset.ActualTargets` completion report).
- Residual (low): a Lucy Cyclone kill while a Bloom window is open (`_diedInBloom` holds the corpse) converts to a count for both sisters instead of Lucy alone. Needs the arrow-in-Cyclone and a Cyclone-move kill in the same window (the window closes on the next action or turn end).
- Residual (low): an ability that starts and never performs stays "in progress" until turn end, so its own kills are dropped as before.
