## Flag lifecycle (`TurnEndedByButton`)

- **Set:** only on the button path. `EndTurnFromButton()` raises `_endTurnButtonPressPending`, calls the unchanged `ForceEndTurn()`, and drops the pending mark in a `finally`. `RequestEndTurn` (base) sets `TurnEndedByButton = true` only when the request actually goes out (turn active, and for the player not refused by `PlayerController`'s introduction check, which returns before calling base). A refused press leaves no mark. `ForceEndTurnSafe` (level end, `EndCurrentPhase`), `RequestEndTurnSafe` and the AI's own requests never set it.
- **Read:** `SwitchTurnIE`, after the existing WaitWhile and before `EndTick()/EndTurn()`, from the faction whose turn is ending.
- **Cleared:** in base `EndTurn()` (right after the read, so it never outlives the switch it belongs to) and in base `StartTurn()` (which `RestartTurn` also goes through). Both overrides (`PlayerController`, `AIController`) call base. Controllers are instantiated per level (`Faction.GetController()` -> `Instantiate`), so nothing carries across levels or restarts. If the level ends before the switch reaches `EndTurn`, the coroutine still calls `EndTurn` (it has no `_levelEnded` check before it), which clears it.
- No statics added (the static method is pure), so no `PlayModeStaticReset` hook needed. Nothing the AI worker thread reads changed.

## Where the pause sits

`SwitchTurnIE`: WaitWhile (actions, sequences, holds) -> read flag -> `EndTick` / `EndTurn` -> `timeBetweenFactionTurns` -> pick next faction -> existing `_levelEnded` / `CanPlayTurn` break -> **turn-start pause (scaled time, `WaitForSeconds`) -> re-check `_levelEnded`** -> `PlayPhaseAnimation` (banner) -> `StartTurn` -> `Tick` -> `UpdateObjectives`. The pause uses the **next** faction's `turnStartPause` and the **ended** faction's flag.

With today's values (`timeBetweenFactionTurns` 0.5 in the scenes until C3 lands, then 0.25): player out of AP -> 0.5 + 0.5 = 1.0 s before the enemy banner now, 0.75 s after C3; End Turn -> gap only; enemy -> player: gap only (player pause 0).

## Decisions I made

- Tier 1: the flag is set inside `RequestEndTurn` while a button press is pending, rather than set before `ForceEndTurn()`, so a press that doesn't end the turn (introductions, not in unit selection) can't leave a stale mark. Same behaviour as the plan otherwise.
- Tier 1: the flag is read before `EndTurn()` and cleared in `EndTurn()` as well as `StartTurn()` (the plan said clear at turn start, restart and level end); this covers level end without a new level-end hook.
- Tier 1: `[Min(0f)]` on the field and a clamp in `TurnStartPauseAfter`, so a negative value means no pause.

## How to see it

1. Select `Content/Controllers/AIController.prefab`: the controller shows **Turn Start Pause 0.5** under Hold Time After Action Completion (PlayerController shows 0).
2. Play a combat level. Spend every AP of the player's units so the turn ends by itself: a short beat, then the enemy banner and turn.
3. Next player turn, press End Turn with AP left: the enemy banner comes after the normal gap only.
4. When the enemy turn ends, the player's banner comes after the normal gap (no extra pause).
5. Win or lose on the last action of the player's turn: no enemy turn starts.
6. Tune it live: change Turn Start Pause on the AIController prefab (or on the instantiated controller in Play mode).
