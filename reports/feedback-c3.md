## How it works

- **Binding:** finds the health attribute through `unit.AttributeSet.RuntimeAttributesMap` with `GlobalSettingsSO.healthAttribute` (what `GetHealthAttribute()` reads, but without its throw before the unit is initialised). Subscribes to `RuntimeEvents.onValueChanged` (the `TrackHealthAttribute` pattern), unsubscribes in `OnDisable` and `OnDestroy`. `LateUpdate` rebinds if the unit has built a new attribute (each `Initialize` makes new ones) and catches up changes that raise no event (silent sets, a max-HP change) without a chip.
- **Show rule:** shown only while the unit is alive, has the attribute, and the sibling `EntityInfoPanel` GameObject is not `activeSelf` (polled in `LateUpdate`; `EntityInfoPanelUI` unchanged). It toggles `Canvas.enabled`, so the component keeps running while hidden and the chip continues underneath the panel. With no panel reference the bar stays hidden.
- **Anchor:** in `Awake` the bar copies the panel's local position (siblings under `UnitInfoHook`), so a variant that moves its panel moves the bar. The canvas then sits 0.775 above that, the centre of the panel's own health bar.
- **Size:** width = footprint width (`EffectivePlacementSize.x`) x `cellWorldWidth` (0.5, the `LevelBase` grid) x 0.6, plus a 1-unit outline each side. The canvas unit is 4/1080 world, i.e. 1 px at 1080p at the default zoom (ortho size 2): a 1-tile bar is about 81 x 4 px inside a 1 px frame. 2-wide units (Masher) get 0.6 world, 3-wide (Deev) 0.9. The Goblin Queen is 1 x 2, so one tile wide, same as a single unit.
- **Chip:** on a drop, the chip's top is the health before the hit, or, if a chip is still showing, the higher of that and where the chip is drawn now; its timer restarts. It holds 0.15 s, then drains to the current health over 0.25 s. A heal that reaches the chip's top ends it. Game (scaled) time, so it freezes with the pause menu and stretches under the hit slow-mo, like the rest of the hit feedback.
- **For the low-HP chunk:** public `Unit`, `HealthAttribute` and `HealthRatio` (0..1, as drawn); the fill colour is a serialized field applied in `Awake`, so the low state can recolour/pulse the `fill` image. No statics.

## Decisions I made

- **Minimal bar instead of `UI_Element_FillBar`:** that component requires seven references (increase, locked, text, ...) and its `OnValidate` touches the text label; a 4 px bar needs only a fill and a chip, so two anchored Images. Same behaviour.
- **Fill and chip drawn by anchor (`anchorMax.x`)**, not filled Images, so no sprite is needed.
- **Chip computed per frame from timestamps** instead of a DOTween tween, so there is no tween to kill on destroy; same timings. Scaled time (pauses with the game).
- **One colour for every side** (the panel has only one; see the question).
- **Position copied from the panel at `Awake`** rather than a per-variant override, so the panel's anchor stays the single source.
- **Deevoted and the decoy get no bar** (their panel never shows).
- **`cellWorldWidth` is a serialized 0.5** (the `LevelBase` grid's cell size); `GridManager` doesn't expose its `Grid`, and I didn't want to touch it.

## Risks and loose ends

- **Zoom:** world-space, like the info panel, so the bar scales with camera zoom (about 2.7 px tall at max zoom-out 3, 5.3 px at 1.5).
- **Grid size:** a level whose grid cell isn't 0.5 would get a bar of the wrong width (all current levels use `LevelBase`'s 0.5).
- **Multi-tile centring:** the bar is centred on the unit's `UnitInfoHook` x, like the panel; if a multi-tile unit's pivot isn't the footprint centre, both are off together.
- **Per-frame cost:** each unit does a dictionary lookup and a float compare in `LateUpdate`. Negligible at our unit counts.
- **Serializer noise** on `UnitBase.prefab` and `Deevoted.prefab` was left out; whoever saves those prefabs next will see those lines appear.
- **Slow-mo:** the chip uses scaled time, so the hit slow-mo stretches it (as the design accepts for the kill flash). Switch to unscaled-but-paused time if it feels slow.
- Not seen in play: sorting against swords and the future-targets avatars, the chip feel, the hide/show flicker during hover sweeps (the panel hides and re-shows on every hover change, so the bar can flash for a frame between two hovers; worth watching).
