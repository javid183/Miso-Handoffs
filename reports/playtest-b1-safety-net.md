- `Systems/AbilitySystem/Abilities/Runtime/RuntimeAbility.cs` (core): the class is now `partial`. In the `EventBasedAnimated` case, `if (suppressAnimation)` became `if (suppressAnimation || !CanPlayEventBasedAnimation())`, so a missing state takes the existing suppressAnimation branch (`_onCompletion = OnCompletionShared; _ActivateAbility();`). That's 2 lines changed and nothing else.
- `Systems/AbilitySystem/Abilities/Runtime/RuntimeAbility.AnimationSafety.cs` (new, core partial): private `CanPlayEventBasedAnimation()` asks the unit's `EntityAnimationHandler` whether the state exists. When it's missing, it logs one `Debug.LogError` naming the ability (title and asset name), the unit (nickname and GameObject name) and the state, with the unit as the log context. The once-per-state memory is a private instance field, `_loggedMissingStateName`, with no static, so no PlayModeStaticReset hook is needed.
- `Systems/AbilitySystem/Abilities/Runtime/AbilityAnimationSafety.cs` (new): a public static class of pure helpers: `ShouldPlayAnimation(bool stateExists, bool suppress)`, `ShouldLogMissingState(stateExists, suppress, stateName, alreadyLoggedStateName)` and `MissingStateMessage(ability, unit, state)`.
- `Animation/EntityAnimation/Runtime/EntityAnimationHandler.cs` (not core): new public `bool HasState(string stateName)`. It returns `animator.HasState(0, Animator.StringToHash(stateName))` on layer 0, the layer `Play` uses. It returns false when the handler is invalid, the animator or its controller is missing, or the name is empty.
- `Systems/AbilitySystem/Abilities/Editor/AbilityAnimationSafetyTests.cs` (new): 10 EditMode tests for the helpers. Namespace `MISO.Core.Systems.AbilitySystem.Abilities.EditorTests`.
- The 3 new files each have their `.meta`, generated by Unity.

All files are UTF-8 with BOM and LF, matching the edited files.

## Decisions I made

- The check lives in `RuntimeAbility` and calls a new `EntityAnimationHandler.HasState`. Putting it inside `EntityAnimationHandler.Play` would not work, because Play has no way to make the ability activate.
- The pure helpers are in a separate public static class, `AbilityAnimationSafety`, rather than public statics on `RuntimeAbility`. This adds no public API to the core class. The only public addition is `HasState` on the handler, which is not core.
- "Once" means once per RuntimeAbility instance and state name: each unit's copy of an ability logs once per Play session. Two units with the same broken ability log once each. Because `Copy()` (MemberwiseClone) also copies the logged name, a copy made after a log stays quiet for that state. This is harmless, so I left `Copy()` untouched.
- A missing `AnimationHandler` (null) counts as a missing state, and the ability activates instead of throwing a NullReferenceException. Today that case would throw in `PlayAbilityAnimation`.

## Risks and loose ends

- This is core (`RuntimeAbility`). The reviewer should check the one changed condition and that the suppress path short-circuits before the check.
- With a missing state, the unit shows no cast animation. The `SetDirection` call is skipped too, the same as with suppressAnimation, so the unit doesn't turn to face the target.
- Abilities that use `TargetSelectionAnimationMode.PauseFrame` call `PlayAbilityAnimation()` during target selection, before `Activate`. If their state is missing, target selection still plays nothing, as it does today. `Activate` then takes the safe path, but `_abilityAnimationPlayStarted` stays true until completion resets it. That is harmless.
- Not covered, a second freeze path: an `abilityActivationFrame` at or beyond the clip's frame count never fires, because `HandleFrameAction` only invokes frames up to total-1. The ability would freeze the same way. This is out of scope for D-052; I'm listing it so the coordinator can decide whether it needs its own task.
- `HandleFrameAction` throws "Empty state found" for a state whose length is 0. That is a different failure, and I didn't change it.
- I did not scan all prefabs for EventBasedAnimated abilities with missing states. The new error will show any of them on first cast.
