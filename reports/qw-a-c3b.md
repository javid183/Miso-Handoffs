# Report: C3b "Fires" cursor (qw-a-c3b)

## What changed
- `CursorSituationCatalog.cs`: new `finalPick` tri-state axis (field "Final Pick", counted in `Specificity`, checked in `Matches` via `MatchesTri`, carried in `CursorSituationSnapshot`). New pure static `FromFinalPick(multipleTargets, requiredTargetCount, pickedCount)`: Any when not multi-target or required <= 1; Yes when `required - picked <= 1`; else No.
- `CursorSituationDriver.Sample()`: sets `finalPick` from the inferred ability, only in TargetSelection / ActionSelection and not when hovering an ability button (ActionSelection first pick goes through the default ability, count 0). Everything else is Any, so single-target attacks resolve exactly as before.
- Catalog asset: every existing row gets `finalPick: 0`; new row "Multi Fire" (priority 66, turnSide Player, overlay None, targetFit Valid, finalPick Yes; specificity 4, same as Basic Attack Valid 62 / Attack Valid 60 / Ability Valid 60 / Surrounding 58, so priority decides and it wins). Edited as YAML (line endings kept) since the MCP was only used for compile/tests.
- No "Multi Pick (adds)" row needed: non-final picks match no finalPick row, so they resolve to the same old row as today.
- Sprite: `cursor_fire.png` is a straight copy of `cursor_attack.png` (same import settings, 32x32, hotspot 6,6 from the row), fresh GUID and sprite ID, sprite renamed `cursor_fire_0`. It looks identical to the attack cursor until THJ repaints it.
- Tests: `Core/UI/Editor/CursorFinalPickTests.cs` (11 tests).

## Acceptance
- Decision helper (counts, multi vs single, first pick count 0, overfilled): Pass (EditMode).
- Catalog resolves Multi Fire for a final-pick snapshot (basic and non-basic attack), old row for No/Any, no fire on an invalid target: Pass (EditMode, loads the real asset).
- Compile, no console errors; full EditMode suite 473/474, only the known red `AIRegressionTest.Baseline_MatchesCurrentAI`: Pass.
- Live cursor in Play (driver `Sample()` wiring, ActionSelection first pick): Not run, needs the verifier.

## Decisions I made
- Driver sets Any (not No) for non-multi abilities and when no ability is inferred; No only for non-final multi picks. Equivalent behavior, keeps old rows matching.
- Skipped finalPick for ability-button hover (the button isn't a pick).
- Row priority 66 (above 62 and 60).

## Risks and loose ends
- Placeholder sprite is identical to the attack cursor, so the change is invisible until repainted.
- `RequiredTargetCount` includes upgrade level; matches what the target counter uses.
- Multi-confirm (`PossibleMultiActivations`) abilities not handled, as scoped.

## How to see it
1. Play a level, select a unit with a multi-target ability (e.g. Lucy's volley).
2. Pick the ability; hover a valid enemy on the first and middle picks: normal attack cursor.
3. On the last pick (and on the first pick of a 1-left ability), the cursor becomes the Multi Fire sprite. Repaint `cursor_fire.png` to see it clearly.
4. Single-target attacks keep the normal cursor.
